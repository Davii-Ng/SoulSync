# Benchmarks

Reproducible measurements for SoulSync. Results land in `results/` and are rendered into [`RESULTS.md`](RESULTS.md) by `report.py`.

Run everything from the repo root with the project's Python environment (`pip install -r backend/requirements.txt datasets psutil websockets`).

| Script | What it measures | Cost |
| --- | --- | --- |
| `eval_emotion.py [--gate] [--external]` | Emotion accuracy, crisis recall and false positives, negation ablation. `--external` scores `dair-ai/emotion`. | free, offline |
| `eval_events.py [--live]` | Calendar-intent regex precision/recall. `--live` scores Gemini field extraction. | free; `--live` ≈ 20 Gemini calls |
| `bench_engine.py` | `analyze_emotion` latency per call | free |
| `bench_load.py` | Concurrency ladder with Gemini/ElevenLabs stubbed (`_stub_server.py`) | free |
| `bench_latency.py` | End-to-end WebSocket latency, real Gemini | 1+ Gemini call per message |
| `report.py` | Builds `RESULTS.md` | free |

Datasets in `datasets/` are generated by `make_datasets.py`; edit the lists there and rerun it.

## End-to-end latency, before vs after

The comparison that matters is the old orchestrator-per-message design against the current single-call pipeline.
Commit `d02fbc8` is the last one where every message went through ADK; commit `526fa2c` introduced the direct pipeline.

```bash
# current code
python benchmarks/bench_latency.py --label current --no-tts

# baseline: check out the old commit in a separate worktree, patch its deprecated model ids, run
git worktree add ../soulsync-baseline d02fbc8
python benchmarks/bench_latency.py --label adk-baseline --repo ../soulsync-baseline --patch-model --no-tts
git worktree remove --force ../soulsync-baseline

python benchmarks/report.py
```

`--no-tts` skips ElevenLabs spend; time-to-text is unaffected. `--limit N` keeps only the first N messages for small quotas.

**Quota warning.** A free-tier Gemini key allows about 20 requests per day for this model, and the ADK baseline makes 2 or more calls per message. A fair run needs a billed key (about 60 calls for the current code, 120+ for the baseline). The script records provider errors and timeouts instead of hiding them, and a run with errors should not be quoted.
